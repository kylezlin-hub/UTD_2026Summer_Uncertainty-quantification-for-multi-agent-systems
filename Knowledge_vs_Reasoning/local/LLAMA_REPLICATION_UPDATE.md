# Llama 8B Replication: Brief-Instance Variability Update

## Critical Issue Discovered

The original Llama replication pipeline in `run_llama_replication.py` has a **methodological flaw** that was revealed by the brief-regeneration robustness check:

### Problem
The pipeline currently **reuses the same fixed briefs** generated by Qwen2.5-7B for the Qwen experiments when running the Llama experiments. This means:
- Brief A (generated by Qwen) is used for **both** Qwen *and* Llama solves
- The Llama results don't control for brief-instance variability
- We can't distinguish "Llama's behavior differs on brief B" from "brief A vs brief B have different properties"

### Impact
The paper's claim "categorical structure (persistent vs. responsive) extends to Llama" becomes ambiguous:
- ✓ Is the categorical structure robust across models?
- ✗ Or is the brief instance fixed and model-independent?

## Solution: Regenerate Briefs for Llama

The Llama replication must:

1. **Generate independent briefs for Llama** (not reuse Qwen briefs)
   - Same seeds offset as brief-regeneration check (FRESH_SEED_BASE range)
   - Same generator prompts (TUTOR_SYSTEM, TUTOR_SYSTEM_BLIND)
   - Same leakage audit logic
   
2. **Use separate output directories**
   - Qwen interventions: `interventions/` → `knowledge_briefs.jsonl`
   - Llama interventions: `interventions_llama/` → `knowledge_briefs_llama.jsonl`
   - Prevents brief cross-contamination

3. **Add `--regenerate-briefs` flag** to `generate_interventions.py`
   - Default: Use cached briefs if they exist (fast, for resuming)
   - `--regenerate-briefs`: Force new brief generation (fresh, for cross-model comparison)
   - Allows fine-grained control
