# Llama 8B Phase 2: Brief Regeneration Design & Implementation

## Overview

The new Llama Phase 2 design uses **independent brief regeneration** to decouple model effects from brief-instance effects. This allows rigorous cross-model comparison of the failure-dependent structure.

---

## Design Architecture

### What Changed

**Before (Old Design):**
```
Qwen Phase 2 generates briefs:
  briefs_A.jsonl (stored in interventions/)
       ↓
       └→ Used by Qwen solves
       └→ REUSED for Llama solves (❌ PROBLEM)

Result: Can't distinguish model differences from brief effects
```

**After (New Design):**
```
Qwen Phase 2 generates briefs:
  Qwen_briefs.jsonl (stored in interventions/)
       ↓
       └→ Used by Qwen solves only

Llama Phase 2 generates FRESH briefs:
  Llama_briefs.jsonl (stored in interventions_llama/)
       ↓
       └→ Used by Llama solves only

Result: Brief effects isolated from model effects
```

### Key Principle

**Brief-instance variability is orthogonal to model choice:**
```
Effect = τ(Model, Brief_instance | Question)
        = Model_effect × Brief_effect × Interaction

By regenerating briefs independently for each model:
- Qwen sees Brief_A generated by Qwen
- Llama sees Brief_B generated by Llama (different instance, same generator prompts)
- Difference in response structure reflects MODEL generality, not brief luck
```

## Implementation Details

### 1. The `--regenerate-briefs` Flag

**Location:** `generate_interventions.py` argparse (line ~806)

```python
ap.add_argument("--regenerate-briefs", action="store_true",
                help="ignore cached briefs and generate fresh ones (use for cross-model studies "
                     "to test brief-instance variability independently of model)")
```

**Behavior:**
- **Default (False)**: Uses cached briefs from `knowledge_briefs.jsonl` if they exist → Fast resumption
- **`--regenerate-briefs` (True)**: Ignores cache, forces fresh generation → Needed for new models

### 2. Caching Logic (Lines 560–572 of `generate_interventions.py`)

```python
def run_generation(args, subset: pd.DataFrame):
    OUT_DIR.mkdir(parents=True, exist_ok=True)
    briefs_path = OUT_DIR / "knowledge_briefs.jsonl"
    results_path = OUT_DIR / "solve_results.jsonl"
    llm = build_pipeline(args)

    # cached briefs
    # If --regenerate-briefs is set, ignore cached briefs and force fresh generation.
    briefs = {}
    if briefs_path.exists() and not args.regenerate_briefs:
        # ✅ CACHE HIT: Load from disk
        for line in briefs_path.read_text(encoding="utf-8").splitlines():
            d = json.loads(line)
            briefs[d["question_no"]] = d
        print(f"[Briefs] Loaded {len(briefs)} cached briefs from {briefs_path}")
    elif args.regenerate_briefs:
        # ✅ REGENERATE MODE: Skip cache entirely
        print(f"[Briefs] --regenerate-briefs is set; forcing fresh brief generation")
        # briefs dict stays empty → forces generation below
    
    done = load_done(results_path)
```

**Decision tree:**
```
Does briefs_path exist AND NOT regenerating?
  ├─ YES → Load from cache (fast)
  └─ NO  → Will generate fresh (either new model or explicit flag)
```

### 3. Brief Generation (Lines 584–594)

```python
for i, row in subset.reset_index(drop=True).iterrows():
    # ... setup ...
    q = DebateQuestion(...)
    
    # CRITICAL LOGIC: Generate only if missing OR regenerate flag is set
    if q.question_no not in briefs or args.regenerate_briefs:
        # Generate blind brief (answer hidden)
        blind_brief, blind_leaked = generate_brief(
            llm, q, options, seed=args.seed, oracle=False
        )
        # Generate oracle brief (answer visible)
        oracle_brief, oracle_leaked = generate_brief(
            llm, q, options, seed=args.seed + 500, oracle=True
        )
        # Store both
        rec = dict(
            question_no=q.question_no, 
            dataset=row["dataset"],
            brief_blind=blind_brief, 
            brief_oracle=oracle_brief,
            blind_leaked=blind_leaked, 
            oracle_leaked=oracle_leaked,
            correct_answer=q.correct_answer
        )
        # Append to briefs file (safe to resume)
        append_jsonl(briefs_path, rec)
        # Cache in memory
        briefs[q.question_no] = rec
    
    # Use briefs for this question (whether cached or fresh)
    brief_texts = {
        "blind": briefs[q.question_no].get("brief_blind", ""),
        "oracle": briefs[q.question_no].get("brief_oracle", "")
    }
    oracle_leaked = bool(briefs[q.question_no].get("oracle_leaked", False))
```

**Key feature:** Condition `q.question_no not in briefs or args.regenerate_briefs` ensures:
- If question has no cached brief → Generate (always)
- If question has cached brief AND `--regenerate-briefs` → Regenerate (override cache)
- If question has cached brief AND NO flag → Use cached (fast)

### Output Separation

**Qwen results:**
```
interventions/
├── knowledge_briefs.jsonl          (Qwen-generated briefs)
├── solve_results.jsonl              (Qwen solver results)
└── intervention_labels.csv
```

**Llama results:**

**Critical:** Each model has its own `knowledge_briefs.jsonl` in its own directory. They don't interfere.

## Execution Flow

### Scenario 1: First Llama Run (Clean Start)

```
run_llama_replication.py --phase 2
  ↓
generate_interventions.py 
  --out-dir interventions_llama/ 
  --regenerate-briefs
  ↓
run_generation(args):
  briefs_path = interventions_llama/knowledge_briefs.jsonl
  
  if exists(briefs_path) and not args.regenerate_briefs:
    → SKIPPED (regenerate_briefs=True)
  elif args.regenerate_briefs:
    → PRINT: "[Briefs] --regenerate-briefs is set; forcing fresh generation"
  
  For each question:
    if question_no not in briefs or args.regenerate_briefs:
      → GENERATE fresh briefs (always true first time)
      → Call generate_brief() with Llama model
      → Write to interventions_llama/knowledge_briefs.jsonl
  
  For each condition (6 total):
    For each repeat (8 total):
      → Call solve_once() using fresh Llama briefs
      → Write result to interventions_llama/solve_results.jsonl
```

### Scenario 2: Resume Llama Run (After Interruption)

```
run_llama_replication.py --phase 2
  ↓
generate_interventions.py 
  --out-dir interventions_llama/ 
  --regenerate-briefs      ← Still set
  ↓
run_generation(args):
  briefs_path = interventions_llama/knowledge_briefs.jsonl (EXISTS from before)
  
  if exists(briefs_path) and not args.regenerate_briefs:
    → SKIPPED (regenerate_briefs=True)
  elif args.regenerate_briefs:
    → PRINT: "[Briefs] --regenerate-briefs is set; forcing fresh generation"
  
  For each question:
    if question_no not in briefs or args.regenerate_briefs:
      → Check if brief for this question already in briefs dict? 
        - FIRST TIME seeing this question in THIS run? → GENERATE
        - Already processed in THIS run? → USE IN-MEMORY CACHE
      → Append to interventions_llama/knowledge_briefs.jsonl (RESUME-SAFE)
  
  done = load_done(solve_results.jsonl) 
    → Skip (question, condition, repeat) combos already completed
  
  For each condition:
    For each repeat:
      if (question_no, condition, repeat) in done:
        → SKIP (already solved)
      else:
        → SOLVE (new)
```

**Key:** The `--regenerate-briefs` flag **persists** even on resume. This is correct behavior:
- It says "use fresh briefs for this model run"
- On resume, questions not yet processed still get fresh briefs
- Questions already processed use their briefs (no duplication)

## Comparison: Seed Management

### Seed Strategy (Unchanged)

Both Qwen and Llama use `--seed 7`:

```python
# Blind brief seed
seed_blind = args.seed + 0        # = 7
# Oracle brief seed  
seed_oracle = args.seed + 500     # = 507
# Solver seeds (per repeat, condition)
seed_solve = args.seed + 1000 * rep + 13 * condition_index
```

**Result:**
- Qwen briefs generated with seeds 7, 507
- Llama briefs generated with seeds 7, 507 (same seeds, DIFFERENT MODEL)
- Each model generates different text with same seed (that's the point!)
- Solver seeds are identical across models (ensures fair comparison)

**Why same seeds for briefs?**
- Not about reproducibility (different model = different output)
- About fair sampling: Both models use same RNG initialization
- Prevents systematic bias in brief quality across models

## Summary

| Aspect | Design |
|--------|--------|
| **Qwen briefs** | `interventions/knowledge_briefs.jsonl` (seed 7, 507) |
| **Llama briefs** | `interventions_llama/knowledge_briefs.jsonl` (seed 7, 507, different model) |
| **Flag behavior** | `--regenerate-briefs` forces new generation regardless of cache |
| **Output isolation** | Separate directories prevent cross-contamination |
| **Resume safety** | JSONL append-only format, done() tracking prevents duplication |
| **Research value** | Decouple model effects from brief effects; test robustness of categorical structure |

The `--regenerate-briefs` flag is the key lever: it ensures Llama gets independent briefs from the same procedural generator, enabling fair cross-model comparison of the failure-dependent structure.
